# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

Это **самостоятельный проект**, не связанный с другими репозиториями (в т.ч. с `wb_sales`).
Общего кода, зависимостей и общей памяти нет.

## Что это

Маленький **статический сайт** — краткий разбор трёх поэм античного эпоса: «Одиссеи» и
«Илиады» Гомера и «Энеиды» Вергилия, по всем песням каждой, плюс режим чтения с полным
текстом (пока для «Одиссеи» и «Илиады» — см. «Критические правила»). Стек намеренно простой:
**чистый Python 3 (стандартная библиотека), без Flask, без сервера, без `pip install`**.
Генератор собирает HTML, который раздаётся как статика.

- Живой сайт: https://rin900work-png.github.io/odyssey-of-homer/
- Remote: `github.com/rin900work-png/odyssey-of-homer` (ветка `main`)

Имя репозитория историческое («odyssey-of-homer»), хотя поэм теперь три и не только Гомера:
адрес сохранён, чтобы не ломать старые ссылки. Название сайта на страницах — «Гомер и Вергилий».

## Команды

```bash
# Пересобрать сайт (docs/) — сразу все три поэмы
python3 build.py

# Проверка синтаксиса перед коммитом
python3 -m py_compile build.py content_odyssey.py content_iliad.py content_aeneid.py

# Посмотреть локально — просто открыть docs/index.html в браузере
open docs/index.html

# Опубликовать: GitHub Pages раздаёт docs/ из ветки main
python3 build.py && git add -A && git commit -m "..." && git push
# Сайт обновится за ~минуту
```

## Архитектура

Генератор + по файлу данных на поэму + тексты + сгенерированный вывод:

- **`content_odyssey.py`**, **`content_iliad.py`**, **`content_aeneid.py`** — ВСЕ данные
  разбора (чистый Python, без зависимостей): `META`, `PARTS` (3 части у Гомера, 2 у «Энеиды»),
  `CHARACTERS`, `THEMES`, `SONGS` (24 песни у Гомера, 12 у «Энеиды»), плюс привязка картинок
  `_SONG_IMG` / `_CHAR_IMG` в конце файла. Содержание правится ЗДЕСЬ. Структура у всех трёх
  файлов одинаковая — `build.py` работает с ними единообразно через список `BOOKS`.
- **`build.py`** — генератор. Список `BOOKS` в начале файла описывает поэмы (slug, модуль
  с данными, переводчик или `None`, обложка для титульной). Читает `content_*.py` + `texts/` →
  собирает страницы в `docs/`. Число песен, склонение слова «песнь» и список поэм в шапке/подвале
  вычисляются из `BOOKS`/`SONGS`, а не захардкожены — добавить ещё поэму не потребует править
  тексты интерфейса. Экранирование HTML через `html.escape` (обёртка `e()`), поэтому в тексты
  `content_*.py` кладём обычный текст, а не сырой HTML.
- **`texts/<slug>/song-NN.txt`** — полный текст песни, один стих на строку. «Одиссея» — перевод
  В. А. Жуковского, «Илиада» — Н. И. Гнедича; оба в общественном достоянии, источник — Викитека.
  У «Энеиды» этой папки пока нет (см. «Критические правила») — `render_reader()` в `build.py`
  корректно пропускает песню, если файла нет, так что страница просто выходит без блока чтения.
- **`static/style.css`** — стили. Базовые переменные — тема «Одиссеи» (эгейская синь);
  `body.theme-iliad`, `body.theme-aeneid` и `body.theme-site` переопределяют акцент (троянская
  бронза / имперский пурпур / нейтральный).
- **`static/img/<slug>/`** — картинки-исходники (общественное достояние, Wikimedia Commons).
- **`tools/`** — вспомогательные скрипты: `fetch_texts.py` (скачать текст «Илиады» с Викитеки),
  `fetch_images.py` (подобрать PD-иллюстрации на Commons), `apply_images.py` (вписать их
  в `content_iliad.py`). Для повседневной правки сайта не нужны.
- **`docs/`** — СГЕНЕРИРОВАННЫЙ сайт.

Карта адресов:

```
docs/index.html                — титульная, выбор поэмы
docs/odyssey.html              — оглавление «Одиссеи»
docs/odyssey-song-01..24.html  — песни «Одиссеи»
docs/iliad.html                — оглавление «Илиады»
docs/iliad-song-01..24.html    — песни «Илиады»
docs/aeneid.html               — оглавление «Энеиды»
docs/aeneid-song-01..12.html   — песни «Энеиды»
docs/song-01..24.html          — заглушки-редиректы со старых адресов «Одиссеи»
```

**Композиция «Одиссеи»:** I. Телемахия (1–4) · II. Странствия (5–12) ·
III. Возвращение и месть (13–24).
**Композиция «Илиады»:** I. Гнев (1–9) · II. Битва у кораблей и Патроклия (10–18) ·
III. Возмездие и выкуп (19–24).
**Композиция «Энеиды»:** I. Странствия (1–6, по образцу «Одиссеи») ·
II. Война в Лации (7–12, по образцу «Илиады»).

## Критические правила

- **`docs/` руками не редактировать.** При каждой сборке `build.py` делает `shutil.rmtree(docs/)`
  и пересоздаёт папку — ручные правки затрутся. Меняем `content_*.py` / `static/` / `texts/`,
  потом `python3 build.py`.
- **Всегда пересобирать перед коммитом**, чтобы `docs/` соответствовал исходникам, иначе живой
  сайт разойдётся с данными. В один коммит идут и исходники, и пересобранный `docs/`.
- **Старые адреса `song-NN.html` не убирать** — это редиректы на `odyssey-song-NN.html`
  для ссылок, которые уже разошлись. Их генерирует `build.py` по флагу `"legacy": True`.
- **Никаких внешних зависимостей** — только стандартная библиотека Python 3. Проект должен
  собираться командой `python3 build.py` на голом Python.
- **`.nojekyll`** нужен, чтобы GitHub Pages раздавал файлы как есть (без обработки Jekyll);
  его пишет `build.py` — не удалять.
- **`texts/` не править вручную** без нужды: число строк в файле = число стихов песни и совпадает
  с канонической нумерацией («Илиада»: 1 → 611, 2 → 877, 3 → 461, 5 → 909…). Лишняя или
  потерянная строка сдвинет всю нумерацию в режиме чтения.
- **У «Энеиды» пока нет режима чтения.** Единственный полный дореволюционный (PD) перевод на
  Викитеке — И. Г. Шершеневича, 1868 (`Энеида (Вергилий; Шершеневич)/Песнь <N>`) — расшифрован
  только для песен III–XII; песни I–II (Дидона, падение Трои) существуют лишь сканом на
  polona.pl, в текст не превращены. Переводы Квашнина-Самарина (1893) и Брюсова/Соловьёва
  (1933) на Викитеке вообще не расшифрованы, только сканы. Если найдётся чистый источник на
  все 12 песен — добавить `texts/aeneid/song-01..12.txt` и `"translator"` в `BOOKS` в `build.py`,
  остальное подхватится само (`render_reader()` уже умеет это отображать).
- Новые картинки кладём в `static/img/<slug>/` (не в `docs/img/`) и привязываем в нужном
  `content_*.py`; `build.py` сам скопирует их в `docs/img/<slug>/`. Только public domain /
  свободные лицензии, с подписью-`credit`. У «Илиады» и «Энеиды» иллюстрации пока не подобраны
  (`_SONG_IMG`/`_CHAR_IMG` в обоих файлах пустые) — это не баг, а недоделанная задача.
- `.DS_Store`, `__pycache__/`, `*.pyc` — в `.gitignore`, не коммитить.

> Примечание: папка `songs/` пустая — исторический артефакт, содержимого там нет.

## Система памяти проекта

В корне проекта — папка `brain/` (в репозитории):

- `brain/daily.md` — журнал сессий. Читать в начале сессии; **дозаписывать** (append) после
  заметных задач и перед паузой/`/compact`, не только в конце.
- `brain/decisions.md` — архитектурные решения: почему так, какие альтернативы отвергли.
- `brain/lessons.md` — баги и паттерны: сложные баги и как решили, что работает/не работает.

Формат записи в `daily.md`:

```
### [YYYY-MM-DD]
- Что сделали
- Что не получилось и почему
- Что делать дальше
```

Память Claude у проекта своя, отдельная от других репозиториев (в т.ч. `wb_sales`).
