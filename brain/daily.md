### [2026-09-14]
- Добавили **третью поэму — «Энеиду» Вергилия** (12 песен, разбор + герои + темы). Сайт
  стал трёхчастным; переименован в «Гомер и Вергилий» (был просто «Гомер» — некорректно
  после добавления Вергилия). Решение и его альтернативы — см. `decisions.md`.
- Композиция «Энеиды» — 2 части (не 3, как у Гомера): I. Странствия (1–6, по образцу
  «Одиссеи»), II. Война в Лации (7–12, по образцу «Илиады») — это реальное деление поэмы
  самим Вергилием (два гексада), решили не подгонять искусственно под 3 части.
- Проверили Викитеку на предмет PD-перевода «Энеиды» для режима чтения (как у Жуковского/
  Гнедича): единственный полный дореволюционный перевод — И. Г. Шершеневича (1868) — на
  Викитеке расшифрован только для песен III–XII, песни I–II (Дидона, падение Трои) есть
  только сканом на polona.pl. Переводы Квашнина-Самарина (1893) и Брюсова/Соловьёва (1933)
  на Викитеке вообще не расшифрованы (только сканы, хотя оба упомянуты как «полные переводы»
  на странице-разметке `Энеида (Вергилий)`). По решению владельца — режим чтения для «Энеиды»
  пока не делаем вообще (ни на 10 из 12 песен, ни частично), ждём чистого источника на все 12.
- `build.py` избавлен от захардкоженных «24 песни» / «обе поэмы»: число песен, склонение
  слова «песнь» (`pesni_word()`) и список поэм в шапке/подвале/титульной теперь считаются из
  `BOOKS`/`SONGS`. Это на будущее — если добавится ещё поэма, тексты интерфейса менять не надо.
- `static/style.css`: третья тема `body.theme-aeneid` (имперский пурпур `#5b3a6b`), сетка
  карточек на титульной `.cards` — 3 колонки (было 2, захардкожено).
- Иллюстрации к «Энеиде» **не делали** — как и у «Илиады» (`_SONG_IMG`/`_CHAR_IMG` пустые),
  это отдельная фоновая задача (Wikimedia отдаёт ~1 картинку в 2–3 минуты, см. `lessons.md`).
- Проверено: `python3 -m py_compile` на всех content_*.py + build.py, `python3 build.py` —
  88 файлов в `docs/`, проверка вложенности HTML-тегов на всех страницах прошла без ошибок,
  визуально просмотрено headless через локальный `http.server` (титульная, `aeneid.html`,
  песня «Энеиды», песня «Одиссеи» — тема и картинки Гомера не пострадали).
- Не сделано, дальше: (1) полный текст «Энеиды» — нужен чистый PD-источник на все 12 песен
  (сейчас есть только неполный Шершеневич); (2) иллюстрации к «Илиаде» (у «Энеиды» уже есть,
  см. ниже).
- **Позже в тот же день:** по просьбе владельца расширили разборы всех 12 песен «Энеиды»
  (больше сюжетных деталей и второстепенных персонажей) и подобрали к ним иллюстрации —
  24 картинки (12 песен + 12 героев), все PD/CC BY, из Wikimedia Commons.
  - `tools/fetch_images_aeneid.py` — по образцу `fetch_images.py`, но пишет в
    `static/img/aeneid/`. Автопоиск закрыл 8 из 12 песен и 9 из 12 героев; для оставшихся
    (песни 1, 5, 9, 10; герои Низ/Эвриал, Камилла, Мезенций) авто-поиск по ключевым словам
    не находил PD-картинку — добили точечным веб-поиском конкретных известных произведений
    (Тёрнер «Дидона, строящая Карфаген», лиможские эмали «Мастер „Энеиды“» ок. 1530–35 —
    целая серия предметов на эту тему, Холлар «Бой Энея с Мезенцием и Лавсом» и т. д.) и
    докачали их напрямую через Commons API по точному названию файла.
  - **Важный баг найден и исправлен:** автопоиск по ключевым словам один раз подобрал
    совершенно не то — фото британского корабля HMS Euryalus 1941 года для персонажа
    «Низ и Эвриал» (совпадение по имени корабля, не по мифологии). Скрипт берёт первый
    подходящий по лицензии результат без смысловой проверки — снимок и его подпись **надо
    визуально проверять**, не вставлять вслепую. Так же обнаружилось, что скрипт путает
    автора картины с именем загрузившего файл участника Викисклада (Тёрнер → «Didier
    Descouens», Кауфман → «Mateus2019»): поле `Artist` в метаданных Commons для многих
    файлов — это загрузивший, а не создатель. Из-за этого **все подписи в `content_aeneid.py`
    написаны вручную по-русски** (как и у «Одиссеи»), а не взяты из автоматического вывода
    `fetch_images.py` — тот годится только как черновой список кандидатов.
  - Сеть в песочнице оказалась нестабильной без `dangerouslyDisableSandbox: true` — без
    этого флага фоновые `python3`-скрипты ловили DNS-ошибки почти на каждом запросе.
  - `build.py`: добавлена обложка `"cover": "song-01.jpg"` для «Энеиды» (Тёрнер, «Дидона,
    строящая Карфаген») — сетка карточек на титульной подровнялась.
